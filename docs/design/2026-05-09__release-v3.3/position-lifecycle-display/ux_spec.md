# UX Spec — Position Lifecycle State Display

## 1. Context

Arc 3 introduces a deterministic five-state position lifecycle: GRACE → LOSING → PROFITABLE → EXIT ZONE, plus UNKNOWN when insufficient data exists. The backend computes state and returns `position_state`, `state_entered_at`, and `days_in_state` from `GET /positions`. This spec defines how those states are surfaced to the user in the Positions page Table View.

§13 constraint: This display is informational only. No automated recommendation or action is generated by the lifecycle state display.

---

## 2. State Definitions (Display Reference)

| State | Condition | Badge Colour | Hex |
|-------|-----------|-------------|-----|
| GRACE | Within first 10 trading days, not moved > 0.5 ATR | Blue | `#2563EB` |
| LOSING | Below entry price by > 0.5 ATR | Red | `#DC2626` |
| PROFITABLE | Above entry price by > 0.5 ATR | Green | `#16A34A` |
| EXIT ZONE | Above entry price by ≥ 2R | Purple | `#7C3AED` |
| UNKNOWN | Insufficient data (no stop or R-target) | Grey | `#6B7280` |

Contrast requirement: all badge text must meet WCAG AA (≥ 4.5:1) against white badge fill (use white text on coloured badges).

---

## 3. Badge Placement

### 3.1 Column

The existing **Status** column in the Table View is extended. The column label remains "Status". The existing GRACE/PROFITABLE/LOSING badge set is superseded by this five-state set.

### 3.2 Badge Format

```
[GRACE — 3d]
```

- State label in all caps
- Em dash separator
- `days_in_state` as integer + "d" suffix
- Badge is a filled pill with white text on the state colour
- Width: content-fit; min-width sufficient to avoid truncation for "EXIT ZONE — 99d"

### 3.3 Tooltip — Next State Trigger

Each badge has a hover/focus tooltip (accessible via `title` attribute or ARIA-described-by) showing the condition that would move the position to the next state:

| State | Tooltip text |
|-------|-------------|
| GRACE | "Exits grace when position moves > 0.5 ATR or after 10 trading days" |
| LOSING | "Exits when price rises above entry by 0.5 ATR" |
| PROFITABLE | "Advances to Exit Zone when P&L reaches 2R target" |
| EXIT ZONE | "Position has reached R-target. Review stop or exit." |
| UNKNOWN | "Set a stop and R-target on the linked trade plan to enable lifecycle tracking." |

Tooltip display: 300ms hover delay; dismiss on mouse-out or focus-out; keyboard-accessible (Tab + tooltip shows on focus).

---

## 4. Table View Column Order

Insert "Status" column (lifecycle state badge) between "Days held" and "Grace Days Remaining":

| ... | Days held | Status | Grace Days Remaining | Tags | Actions |
|-----|-----------|--------|---------------------|------|---------|

Grace Days Remaining column remains for grace period day count. Status badge provides the state label. Both are visible simultaneously — they are complementary.

---

## 5. Grid View

Grid cards display the lifecycle state badge (without days_in_state inline — space is limited). Tooltip still applies. Position: below "Days held" metric on the card.

---

## 6. Empty / Null State

If `position_state` is null (positions created before migration, pending back-fill): display UNKNOWN badge. Do not display a dash or empty cell — UNKNOWN is a valid state.

---

## 7. UNKNOWN State UX Note

UNKNOWN is not an error state. It is displayed in the same styled pill as other states, using grey. The tooltip directs the user to set a stop and R-target on their trade plan. No alert or warning aside from the tooltip.

---

## 8. Loading Behaviour

Badge is part of the position row. Skeleton row covers the badge cell during initial load. No badge-specific loading state.

---

## 9. Responsive

On narrow screens where the table collapses to cards: display badge as a full-width pill at the top of each card (above ticker). Tooltip accessible on tap (tap to show, tap elsewhere to dismiss).

---

## 10. Accessibility

- Badge colour is never the sole differentiator — state label text is always present
- Tooltip available via keyboard focus on badge element
- Screen reader: `aria-label="Position state: GRACE, 3 days in state"` on badge element

---

## 11. Design Decisions

| Decision | Rationale |
|----------|-----------|
| Days-in-state inline with badge | Eliminates need for a separate column; badge is more scannable |
| Tooltip for next trigger | Informs user without cluttering table layout |
| Retain Grace Days Remaining column | Preserves granular "Day N of 10" count; complements state badge |
| EXIT ZONE in purple | Distinct from PROFITABLE (green) — signals a materially different decision context |
| UNKNOWN in grey | Neutral, not alarming — insufficient data is a configuration gap, not a risk |

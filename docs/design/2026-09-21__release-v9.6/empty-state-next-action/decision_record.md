# Decision Record — Name One Primary Next Action in Every Empty State

## 1. Problem

The v1.8 microcopy pattern (`design_system.md` §Data States) makes each empty-state **body** state a next action in words, but only a minority of call sites provide a clickable route to it, so a first-time or cleared view can be a dead end. The rule needs to become "one primary next-action *link*", with a defined scope so the story's AC ("0 audited empty states without a next-action link") is measurable.

## 2. Decision

### 2.1 The rule

Every user-facing empty state renders **exactly one** primary next-action link or button, labelled `"<Verb> <object>"` (2–4 words, sentence case, no trailing period — e.g. "Run the screener", "Create a trade plan"), leading to the place that would populate the view.

Two implementations count as satisfying it:
1. **`DataState`'s existing `emptyAction`** node inside the empty region (page-level and section-level empty states); or
2. **For `DashboardCard` empty states:** the enclosing card's `to` link (`DashboardCard` wraps the whole card in a `<Link>` when `to` is set). This continues the standing rule that a second inner CTA competes with a card's own click-through (`design_system.md` §Data States, compact variant). A card with **no** `to` gains one; it does not gain an inner button.

### 2.2 Scope exclusions

An empty state is **excluded from the audit** (recorded with its reason, not silently skipped) only when *no user action could populate it* — the view is filled exclusively by the system. Exclusions must state that reason in the audit table.

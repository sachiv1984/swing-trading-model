# Positions Table — Data Dictionary

---

## 1. Purpose

This document is the canonical reference for every field in the `positions` table. It defines the meaning, type, nullability, derivation rule, currency semantics, and lifecycle constraints for each field.

All implementations (backend API, analytics engine, migration scripts, test fixtures) must be consistent with this dictionary. In case of conflict between this document and any other source, this dictionary prevails (subject to `docs/specs/Specs_Index.md` conflict resolution order).

---

## 2. Lifecycle Note

The `positions` table serves **both open and closed positions** within a single row. The `status` field determines lifecycle state. All `exit_*` fields are `NULL` while `status = 'open'`. Queries that span both states must explicitly account for this; failure to filter by `status` is a common source of incorrect P&L aggregations.

### 3.3 Entry Fields

| Field | SQL Type | Nullable | Description |
|-------|----------|----------|-------------|
| `entry_date` | DATE | NO | Calendar date on which the position was opened. Used for `holding_days` calculation and tax-year attribution of open positions. |
| `entry_price` | DECIMAL(10,4) | NO | Entry price **in GBP** for every market: the request's native entry price divided by `fx_rate` for US positions, unchanged for UK (`add_position()` writes `entry_price_gbp`). The native entry price is `fill_price`; the broker's actual fill is `user_fill_price`. *(Corrected v0.4: earlier versions said native currency; Data Model & Domain Schema Owner ruling, doc fix, `ESC-EXEC-20261013-05`.)* |
| `fill_price` | DECIMAL(10,4) | YES | The entry price in **native** currency (USD for US, GBP for UK), copied from the request's `entry_price` and set on every insert by `add_position()`. Stop, P&L and display readers use it as the native entry for US positions. It is not the broker fill: that is `user_fill_price`, the request's optional `fill_price`, NULL when not supplied. |
| `user_fill_price` | DECIMAL(10,4) | YES | The broker's actual fill price in **native** currency, as the user entered it: the request's optional `fill_price`, which `add_position()` stores here unchanged. NULL when not supplied. Used for slippage only: `trade_history.fill_price` is copied from it at exit. No stop, P&L or cost calculation reads it. *(Row added v0.6, ST-13, BLG-SPEC-190.)* |
| `fill_currency` | VARCHAR(3) | YES | Currency of `fill_price`: `"GBP"` or `"USD"`, set from `market` on every insert. |
| `fx_rate` | DECIMAL(10,6) | YES | GBP/USD exchange rate at time of entry: the user-supplied rate, else the live rate at entry, for US positions; `1.0` for UK positions. Converts the native entry and fees to GBP for `entry_price`, `fees_paid` and `total_cost`. |
| `shares` | DECIMAL(10,4) | NO | Number of shares held. Fractional shares allowed (4 decimal places). Changed from INTEGER to DECIMAL in migration v1.2→v1.3. |
| `total_cost` | DECIMAL(12,2) | NO | Total cost of the position **in GBP**, including fees. Derivation at entry: UK `total_cost = entry_price × shares + fees_paid`; US `total_cost = fill_price × shares / fx_rate + fees_paid`, which equals `entry_price × shares + fees_paid` because `entry_price` is already GBP (§5.1). Reduced proportionally on partial exit, with `fees_paid`; stored rounded to 2 dp. |
| `fees_paid` | DECIMAL(10,2) | NO | Total fees paid at entry, in GBP, reduced proportionally on partial exit. `NOT NULL`, no default — re-applied live 2026-10-05 (`data_model.md` DS-23); an insert that omits it fails rather than recording £0. |
| `fee_type` | VARCHAR(20) | YES | Fee calculation method applied (e.g. `"flat"`, `"percent"`). Informational — does not affect `fees_paid` which is always the computed amount. Added in migration v1.1→v1.2. |
| `strategy_version_at_entry` | VARCHAR(10) | YES | Active `strategy_rules.md` version at entry (`get_current_strategy_version()`), stamped by `add_position()`. Forward-only: never rewritten, and NULL for positions entered before the column was added (v8.0, ST-01). Added v0.8. |

### 3.4 Stop and Risk Fields

| Field | SQL Type | Nullable | Description |
|-------|----------|----------|-------------|
| `initial_stop` | DECIMAL(10,4) | YES | Stop-loss price at entry, in native currency. Set using `atr_multiplier_initial × atr` below entry price (per `strategy_rules.md §4`). NULL if not set at entry. |
| `current_stop` | DECIMAL(10,4) | YES | Current trailing stop price, in native currency. Updated as price moves in favour; uses `atr_multiplier_trailing` once position is profitable. NULL if position has been closed. |
| `atr` | DECIMAL(10,4) | YES | Average True Range value at entry, in native currency. Used for stop calculation. NULL if ATR data was unavailable at entry. |
| `atr_source` | VARCHAR(10) | YES | Where the stored `atr` came from: `fetched` (computed from market data), `user` (typed at entry) or `fallback` (no ATR could be fetched at entry, so 2% of the entry price was used). Written at entry and whenever ATR is freshly fetched on a recompute. NULL for positions entered before the column was added and not freshly recomputed since (`data_model.md` DS-25). Added v0.8. |
| `atr_calculated_at` | TIMESTAMPTZ | YES | UTC timestamp of the most recent fresh `atr` computation; not stamped when a stored ATR is merely reused. NULL if never recomputed since the column was added (`data_model.md` DS-22). Added v0.8. |
| `stop_calculated_at` | TIMESTAMPTZ | YES | UTC timestamp of the most recent `current_stop` recalculation against ATR, by the on-load path (`GET /positions/analyze`) or the nightly job (`POST /positions/nightly-stop-update`). The grace-period carry-over does not stamp it. NULL if never recomputed since the column was added (`data_model.md` DS-22). Added v0.8. |
| `stop_calculation_source` | VARCHAR(10) | YES | Which path last recalculated `current_stop`: `on_load` or `nightly`. Written together with `stop_calculated_at`. NULL until the first recompute after the column was added (`data_model.md` DS-26). Added v0.8. |
| `active_atr_multiplier` | DECIMAL(4,2) | YES | The ATR multiplier behind the current `current_stop` (`calculate_trailing_stop()`'s returned multiplier: 5 while losing, 2 once profitable, `strategy_rules.md` §7.2/§11). Unitless. NULL if never recomputed since the column was added (`data_model.md` DS-22). Copied to `trade_history.active_atr_multiplier` at exit. Added v0.8. |
| `stop_frozen_reason` | VARCHAR(20) | YES | Why the last post-grace recompute kept `current_stop` instead of recalculating it. Only value: `atr_unavailable` (no ATR could be fetched and none was stored), enforced by CHECK. Written by the on-load path (with or without a live price) and the nightly job; cleared to NULL by the next post-grace recompute that has an ATR; never written during grace (`strategy_rules.md` §6.3). Drives the Positions frozen-stop indicator (`data_model.md` DS-32). Added v0.8. |
| `stop_last_moved_date` | DATE | YES | The UTC date of the recompute (on-load `GET /positions/analyze` or the nightly job) that last raised `current_stop` under the §7.3 ratchet. Written only when the stored stop goes up from a non-null value; a recompute that keeps the stop and an in-grace or skipped position leave it unchanged. NULL until the first move. Read-only on `GET /positions`; drives the Dashboard Today list's Stops moved group (`data_model.md` DS-40). Added v0.9. |
| `previous_stop` | DECIMAL(10,4) | YES | Native-currency `current_stop` immediately before the move recorded in `stop_last_moved_date`, written in the same update. NULL until the first move (`data_model.md` DS-40). Added v0.9. |

### 3.5 Live Price and Performance Fields

| Field | SQL Type | Nullable | Description |
|-------|----------|----------|-------------|
| `current_price` | DECIMAL(10,4) | YES | Most recently recorded price in native currency. Updated by the daily price refresh process. NULL before first price update or after position closure. |
| `holding_days` | INTEGER | YES | Calendar days held, measured from `entry_date` to the current date (open positions) or `exit_date` (closed positions). Updated daily for open positions. | `pnl` | DECIMAL(12,2) | YES | **Unrealised** P&L in GBP for an open position: `(current_price − native_entry) × shares ÷ live GBP/USD rate` for US, `(current_price − entry_price) × shares` for UK, **not net of `fees_paid`** (§5.2). | `pnl_pct` | DECIMAL(10,2) | YES | P&L as a percentage of `total_cost`. Formula: `pnl / total_cost × 100`. Also returned as `pnl_percent` by the API layer (alias). Default `0`. Nullable `YES` from v0.5: the column has a `DEFAULT` but no `NOT NULL`, matching `data_model.md` v2.60 and the live schema. |

## 5. Key Derivation Rules

### 5.1 `total_cost` (GBP)

```
UK position:  total_cost = (entry_price × shares) + fees_paid
US position:  total_cost = (fill_price × shares / fx_rate) + fees_paid
           ≡ (entry_price × shares) + fees_paid      (entry_price is GBP = fill_price / fx_rate)
```

Worked US example: `fill_price` $100, 10 shares, $1.50 FX fee, `fx_rate` 1.25. `position_service.py` computes `(1000 + 1.50) / 1.25` = £801.20; `entry_price` = £80, `fees_paid` = £1.20; `1000 / 1.25 + 1.20` = £801.20. (The pre-v0.4 formula `entry_price × shares / fx_rate` divided by the rate twice: £641.20.) Partial exits reduce `total_cost` and `fees_paid` proportionally, so the identity holds at entry, not necessarily after a partial exit.

`total_cost` is the GBP book cost. It is the denominator for `pnl_pct`.

### 5.2 `pnl` (GBP)

```
Open position (UK):   pnl = (current_price − entry_price) × shares
Open position (US):   pnl = (current_price − fill_price) × shares / live_fx_rate
```

**Basis (v0.7, ST-23, BLG-SPEC-198; Data Model & Domain Schema Owner ruling `ESC-EXEC-20261104-04`, 2026-11-04 — spec follows code):** open-position `pnl` is the native price move converted at the **live** GBP/USD rate (USD per £1) and is **not net of `fees_paid`**. This is what `calculate_position_pnl()` (`backend/utils/calculations.py`) returns to `get_positions_with_prices()` (`GET /positions`, and the stored column via the on-load and nightly update) and `portfolio_service.py`, so it is the figure every page displays. For US positions the native entry is `fill_price`; a row with a NULL `fill_price` uses `entry_price × fx_rate`. `entry_price` is GBP and must not be subtracted from a native price (v0.4).

**Rationale:** the dictionary (entry-time rate, fees deducted) described a figure no surface displays. Changing the code instead would change displayed P&L on Positions, Dashboard and Portfolio, which needs a design pass. Documenting the live figure makes it reproducible from this dictionary.

**Difference from realised P&L:** a closed trade's realised P&L is `trade_history.pnl = net_proceeds_gbp − total_cost`, written once by `exit_position()` (`metrics_definitions.md` §Realized / Unrealized P&L Split). It is net of entry and exit fees, and its cost leg is at the entry-time rate and its proceeds leg at the exit rate, so it includes currency movement on the principal. Unrealised `pnl` converts only the price move, at today's rate, gross of fees. The two can therefore differ for the same position at the moment of exit. Whether to align them is tracked as `BLG-SPEC-218`.

**Closed positions:** `positions.pnl` is not rewritten when a position closes; it keeps the last unrealised value. Use `trade_history.pnl` for realised P&L.

### 5.3 `pnl_pct`

```
pnl_pct = pnl / total_cost × 100
```

The API returns this field as both `pnl_pct` (DB column name) and `pnl_percent` (API alias). Both values are identical.

### 5.4 `holding_days`

```
Open position:   holding_days = (today − entry_date) in calendar days
Closed position: holding_days = (exit_date − entry_date) in calendar days
```

Updated daily for open positions by the daily refresh process.

### 5.5 Tax-Year Attribution

Closed trades are attributed to the UK tax year containing their `exit_date`. The UK tax year runs from **6 April** to **5 April** of the following year. `year = YYYY` corresponds to the tax year starting 6 April YYYY. See `docs/specs/api_contracts/reports_endpoints.md` for full rules.

## 6. Currency Semantics Summary

| Field | Currency |
|-------|----------|
| `fill_price`, `user_fill_price`, `current_price`, `exit_price`, `initial_stop`, `current_stop`, `atr` | Native (USD for US, GBP for UK) |
| `entry_price` | Always GBP (`fill_price / fx_rate` for US) |
| `fx_rate` | GBP/USD rate (US positions; `1.0` for UK) |
| `total_cost`, `fees_paid`, `pnl` | Always GBP |
| `pnl_pct` | Percentage (dimensionless) |

`total_cost`, `fees_paid` and `pnl` use `DECIMAL(12,2)`. Price fields, including the GBP `entry_price`, use `DECIMAL(10,4)`.

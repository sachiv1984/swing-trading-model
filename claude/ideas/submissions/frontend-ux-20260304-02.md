# Idea: Accessibility Baseline for Critical UI Components

## 1. Problem Statement

The trading UI has no documented accessibility requirements and no baseline accessibility assessment has been performed. Users who rely on keyboard navigation, screen readers, or high-contrast display modes may be unable to use critical workflows — position entry, reviewing stops, actioning exit recommendations. In the UK, the Equality Act 2010 creates an obligation to make services reasonably accessible; for a financial tool where an inaccessible interface could mean a missed exit recommendation and financial loss, the cost of inaccessibility is direct.

## 2. Strategic Alignment

Section reference: §3 — Human-in-the-loop execution model

Alignment rationale: The human-in-the-loop model requires the human to be able to receive and act on system recommendations. If the interface is inaccessible to a user with a visual or motor disability, the human-in-the-loop model fails for that user — not because of strategy design but because the interface excludes them. Accessibility is a direct enabler of the human-in-the-loop intent.

## 3. Proposed Solution

Define a minimum WCAG 2.1 AA compliance baseline for the trading UI. Conduct a targeted accessibility audit of the five most critical components: position entry form, portfolio positions list, stop distance display, exit recommendation display, and analytics summary. Document findings in `docs/ux/accessibility_audit_baseline.md`. For each component, report: current compliance gaps, severity (blocker vs. best-practice), and recommended remediation. High-severity gaps become backlog items in the next cycle.

## 4. Expected Value

Makes accessibility posture explicit for the first time. Provides a prioritised remediation list. Reduces legal risk. May expand the user base to include users with accessibility needs who currently cannot use the system. Measurable as: number of WCAG 2.1 AA violations in critical components before and after remediation.

## 5. Effort Estimate

# Idea: Delivery State Report (CI-Generated)

## 1. Problem Statement

The PMO Lead currently reconstructs delivery state by reading `.claude_current_state.json`, the backlog slice, and the execution state JSON separately. For a single work item this is manageable; for a release with 6 EPICs and 30 tasks, deriving current state across all items requires significant manual effort. There is no single artefact that shows all active work items, their current phase, gate completion status, and any overdue escalations in one place. State visibility is bottlenecked on the PMO Lead being available to aggregate it.

## 2. Strategic Alignment

Section reference: PMO Lead §5.1 — State Validation ("the PMO Lead must know the system-derived current state at all times")

Alignment rationale: The PMO Lead's mandate is to ensure every work item state is always computable and auditable. A CI-generated delivery state report is the automation-layer implementation of this principle: state becomes visible to all stakeholders in under one minute, without requiring the PMO Lead to manually aggregate it. This directly enables the "automation handles flow; humans handle judgment" success criterion.

## 3. Proposed Solution

Add a CI step (triggered on push to any exec/ branch) that reads `.claude_current_state.json` and the relevant backlog slice and writes `delivery_state_report.md` to the repository root. The report shows: each active EPIC and task, current phase, last gate completed, days since last update, and any overdue escalation flags. The report is committed to the branch and linked from the PR description. This is a read-only report — it does not modify state.

## 4. Expected Value

Reduces PMO Lead time spent reconstructing delivery state from ~15 minutes per check to zero (state is always current in the report). Enables any stakeholder to read delivery state without interrupting the PMO Lead. Escalations become visible immediately rather than on the next scheduled check. Measurable as time-to-state-visibility per enquiry.

## 5. Effort Estimate

- [x] Medium — 1–3 weeks

Constraints or dependencies: Requires a Python or shell script to parse the state JSON and generate markdown output. CI must have write permission to commit the report file.

## 6. Reversibility

- [x] Fully reversible — no lasting effects

Reasoning: The report is a generated artefact; removing the CI step reverts to the current manual state with no data loss.

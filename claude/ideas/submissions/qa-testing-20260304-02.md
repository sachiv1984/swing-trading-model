# Idea: Test Automation Readiness Assessment

## 1. Problem Statement

The current test suite contains a mix of manually executed scenarios and automated CI checks, but there is no systematic assessment of which critical test scenarios could be automated and which genuinely require manual execution. Without a deliberate assessment, automation investment is opportunistic — whoever happens to have capacity writes automation for whatever they find easiest to automate, rather than for the highest-risk, highest-value scenarios. The result is an automation portfolio that may not cover the critical paths that matter most.

## 2. Strategic Alignment

Section reference: Director of Quality §4.4 — "ensure automation and regression frameworks are robust"

Alignment rationale: A "robust" automation framework requires knowing what should be automated. Without an assessment, "robust" is aspirational. The automation readiness assessment is the analytical prerequisite for making deliberate, value-optimising automation investments. It transforms the automation programme from reactive to intentional.

## 3. Proposed Solution

Produce a one-time `docs/team_skills/quality/test_automation_assessment.md` — a Class 4 planning document classifying all known test scenarios as: (a) already automated (document where), (b) suitable for automation with justification, or (c) requires manual execution with justification. For "suitable for automation" scenarios, provide a priority ranking based on: failure frequency, criticality of the behaviour, and test execution cost. The top 10 automation candidates form the input to the next cycle's automation roadmap.

## 4. Expected Value

Makes automation opportunities explicit and prioritised. Enables a data-driven automation investment decision rather than ad hoc automation. Expected to identify 5–10 high-value automation candidates in the first pass, and to reveal whether current automation covers the right scenarios or the convenient ones.

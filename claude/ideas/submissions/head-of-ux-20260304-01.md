# Idea: Daily Trading Workflow Journey Map

## 1. Problem Statement

The system has been built feature by feature but there is no documented canonical user journey for the daily workflow a trader actually follows when using it. Features are designed in isolation: the position entry form, the analytics section, and the stop display were each built without a documented understanding of how they fit into the user's actual daily routine. The result is that the user must mentally construct their own workflow from disconnected features. When new features are designed, the question "where does this fit in the daily workflow?" cannot be answered with reference to a canonical document — it is answered by guess or assumption.

## 2. Strategic Alignment

Section reference: §3 — Human-in-the-loop execution model

Alignment rationale: The human-in-the-loop model is not just a system architecture principle — it describes the daily interaction between a human and the system. Designing the interface to support that daily interaction well requires understanding what it looks like. A journey map is the canonical UX document that describes the human's side of the human-in-the-loop relationship, making it possible to evaluate whether the system serves that relationship well.

## 3. Proposed Solution

Create `docs/ux/daily_workflow_journey.md` — a canonical UX document showing the step-by-step daily workflow a trader follows: (1) open dashboard and check open positions, (2) review stop distances and assess any positions approaching stop, (3) check for exit recommendations triggered since last login, (4) review portfolio heat and available cash before considering new positions, (5) enter any new positions. For each step, document: the system feature that supports it, the decision the user makes, and the information they need. Use this as the design anchor for all future UX decisions.

## 4. Expected Value

Provides a shared design reference for all UX and product decisions. Enables prioritisation of features based on frequency-of-use in the daily workflow. Prevents features from being designed in isolation without regard to how they fit the user's actual task sequence. Measurable as: reduction in UX design decisions made without reference to the journey map (target: all future design decisions reference the map).

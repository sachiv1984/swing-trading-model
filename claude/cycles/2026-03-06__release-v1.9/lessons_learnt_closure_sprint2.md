### Friction Item 1

**Classification:** Type B — Process gap: Phase 3 execution lessons learnt not appended for Sprint 2.

**Recurrence:** No — first occurrence of this specific variant (Sprint 2 execution lessons absent).

**What happened:**
The execution prompt (Phase 3) is responsible for appending a Sprint 2 execution section to `lessons_learnt_cycle.md`. This did not occur during Sprint 2 execution — no Phase 3 section for Sprint 2 was appended. The post-ship closure engine discovered only a Phase 4 section (delivery verification, 2026-03-13) and the original Phase 4 placeholder in the IMP-28 format.

**Where in the routine:** STEP 8 — Lessons Review (discovery).

**Root cause:** Execution prompt v1.x does not have an explicit obligation to append to `lessons_learnt_cycle.md` when execution is resumed mid-cycle (Sprint 2 of a multi-sprint release). The lessons append is designed for the first execution pass; re-entry path for Sprint 2 may not have triggered the append step.

**Blast radius analysis:**
- No lessons from Sprint 2 execution are captured (friction items from the 3 hotfix PRs post-merge, doFetch unwrapping bug discovery, etc.).
- Partially mitigated: Phase 4 delivery verification captured the root cause (no dev environment, code-inspection QA only) in lessons_learnt_cycle.md Phase 4 section.
- Recovery cost: Low — the operational gap is noted here. Future cycles should check for Sprint 2 execution lessons explicitly.

**Process patch:**

→ Deferred:
  - File: `claude/system/execution_prompt.md`
  - Section: Sprint execution lessons learnt append step
  - Change required: When a sprint execution is resumed for Sprint 2+ of a multi-sprint release, the execution prompt should explicitly append a Phase 3 section to `lessons_learnt_cycle.md` at sprint close, even if a Phase 3 section already exists for Sprint 1.
  - Owner: Head of Specs Team
  - Target: Before v1.10 sprint execution begins

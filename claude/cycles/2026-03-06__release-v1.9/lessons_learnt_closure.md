### Friction Item 1

**Classification:** Type B — Semantic Mismatch: multi-sprint release requires non-standard post-ship closure path.

**Recurrence:** No — first multi-sprint release cycle in this project.

**What happened:**
The post_ship_closure.md prompt (v1.4) is designed for single-sprint releases. v1.9 has 2 planned sprints. Running `run post-ship` after Sprint 1 closes Sprint 1 correctly but leaves Sprint 2 (ST-01–05, ST-12) without a clear re-entry path: the lifecycle guard for `run sprint` requires `Sprint_Planning_Complete` or `Executing`, but post-ship sets status to `Closed`. The sprint 2 items were confirmed in `sprint2_deferred` and return to backlog, but the next command path requires manual understanding of the multi-sprint context.

**Where in the routine:** STEP 10 — Global State Update; STEP 0 product owner confirmation (Sprint 2 handling decision).

**Root cause:** The lifecycle state machine (`lifecycle_schema.json` and `shared_standards.md §10.1`) does not define a valid transition path for multi-sprint releases where Sprint N post-ship should re-enable Sprint N+1 execution within the same cycle.

**Blast radius analysis:**
- What would have propagated: Any future 2-sprint release will require the same manual coordination. As Sprint 2 is executed, the next `run sprint` invocation will fail the lifecycle guard (status = Closed, not Sprint_Planning_Complete).
- When it would have surfaced: At next `run sprint` invocation for Sprint 2 of v1.9.
- Recovery cost if uncaught: Low (user can manually set status to Sprint_Planning_Complete); medium if the sprint execution engine is run in strict mode.

**Process patch:**

→ Deferred patch:
  - File: `claude/system/lifecycle_schema.json` and `claude/system/shared_standards.md §10.1`
  - Section: Lifecycle Guard entry states table — Sprint Execution row
  - Change required: Add `Closed` (with `sprint_planning.total_sprints > sprint_planning.sprint_number` condition) as a valid from-state for Sprint Execution. This allows post-ship to close Sprint N while Sprint N+1 can still be executed within the same cycle. Alternatively, add a new intermediate state `Sprint_N_Closed` as a valid from-state for Sprint Execution.
  - Owner: Head of Specs Team
  - Target: Before Sprint 2 execution begins (2026-03-06__release-v1.9)

### Friction Item 1

**Classification:**
- Type A — Governance Drift: A documented rule or header requirement was ignored or missed

**Recurrence:** Not checkable (no prior closure file)

**What happened:**
A prior post-ship closure run was executed and committed (git commit 027f6ce: `[GOVERNANCE] Post-ship closure complete: 2026-03-02__release-v1.7`). A subsequent remote merge commit (5af4412: `Merge branch 'main' of https://github.com/sachiv1984/swing-trading-model`) overwrote two governance artefacts: (a) `closure_record.md` was deleted from the merge result, and (b) `.claude_current_state.json` was reverted to `status: Verified` rather than the post-closure `status: Closed`. The full post-ship closure engine had to be re-executed in a new session.

**Where in the routine:**
STEP 11 — Commit (the commit was made, but push/pull sequencing allowed a remote merge to overwrite it)

**Root cause:**
Process gap — the post-ship closure commit was made to a local branch that had not been pushed to origin before a `git pull` or remote merge was performed. The remote branch HEAD was ahead, and the merge resolved in favour of the remote state, discarding local governance artefacts.

**Blast radius analysis:**
- What would have propagated: The cycle would have remained in `status: Verified` indefinitely unless re-run. The `closure_record.md` absence would prevent any future audit confirming the cycle was formally closed. The next cycle could still have opened (since `next_cycle_unblocked: true`), but the governance record would be incomplete.
- When it would have surfaced: Next session start (CLAUDE.md §0 would read status: Verified, triggering a re-run) — or if an audit checked for closure_record.md existence.
- Recovery cost if uncaught: Low-to-medium (single session re-run, all source artefacts intact) — but the gap is non-trivial from a governance integrity standpoint.

**Process patch:**

→ Deferred patch (cannot apply this run):
  - File: claude/system/post_ship_closure.md
  - Section: STEP 11 — Commit
  - Change required: Add an explicit instruction at the end of STEP 11: "Push the governance commit to origin BEFORE performing any `git pull` or remote sync. The closure commit must be the HEAD of origin before any remote merge is allowed."
  - Owner: Head of Specs Team (prompt owner)
  - Target: Next governance prompt revision cycle

- What would have propagated: Standard mode flagging prevents a halt, but the prompt ambiguity could cause a different agent to interpret this as a hard gate in strict mode.
- When it would have surfaced: Any future foundation-type release with no scope doc would encounter the same ambiguity.
- Recovery cost if uncaught: Low (clarification only) — the underlying closure is complete regardless.

**Process patch:**

→ Deferred patch (cannot apply this run):

Mark STEP 4.1 as N/A rather than ⚠."

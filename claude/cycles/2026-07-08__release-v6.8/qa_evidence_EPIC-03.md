GitHub Actions CI failed this test deterministically (both the initial attempt and its 1 configured retry) on PR #947. Root cause: a genuine route-registration-order bug in the test itself — the delayed arc5-compliance route was registered *before* `mockFallback`'s generic catch-all, so per Playwright's reverse-registration-order matching, the catch-all (registered last) won the race and fulfilled instantly, starving the delayed handler and making the loading-skeleton assertion non-deterministic. This is the same defect class documented in `shared_standards.md §18`'s route-ordering advisory (added during this same EPIC's ST-16), which this test itself failed to follow.

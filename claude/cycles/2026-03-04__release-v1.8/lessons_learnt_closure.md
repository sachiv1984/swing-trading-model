### Friction Item 1

**Classification:** Type A — Governance Drift: a planning artefact that should have been created during release planning was not created.

**Recurrence:** Yes — v1.7 post-ship closure (CL-LL-02) also found no scope document for the release. Different root cause: v1.7 was a foundation/governance release (scope artefact substituted by stage4_backlog_slice.md). v1.8 is a user-facing feature release — a scope document was expected but none was created during planning.

**What happened:**
STEP 4.1 required locating `docs/product/scope/scope--{id}-{slug}.md` for v1.8. Reviewing `docs/product/scope/`, no v1.8-specific scope document exists. The existing files are for v1.6 (3.2 position sizing) and v1.6.1 (QWB quick wins bundle). The v1.8 planning artefacts consist of `stage4_backlog_slice.md` and `sprint_goal.md` — sufficient for execution but not an explicit scope document per the closure prompt. Standard mode: flagged and continued. `stage4_backlog_slice.md` treated as the accepted scope record.

**Where in the routine:** STEP 4.1 — Scope document.

**Root cause:** The release planning engine does not mandate creation of a `scope--{id}-{slug}.md` document as a required artefact. Scope is implicitly captured in the backlog slice and sprint goal, but without an explicit scope document, STEP 4.1 has nothing to mark Superseded. This gap will recur on any release where a standalone scope document was not created during planning.

**Blast radius analysis:**
- What would have propagated: Any future release without a scope document will hit the same STEP 4.1 flag. If strict mode is used, this would halt post-ship closure.
- When it would have surfaced: At post-ship closure — every cycle.
- Recovery cost if uncaught: Low (standard mode proceeds); medium in strict mode (halt requires manual resolution).

**Process patch:**

→ Deferred patch:
  - File: `claude/system/release_planning_prompt.md`
  - Section: Write scope section or STEP 1 (release context loading)
  - Change required: Add explicit creation of a `scope--{cycle_id}-{slug}.md` document as a required output of release planning, with content: release version, feature name, backlog items in scope, items explicitly deferred, and a supersession note template for post-ship closure. This makes STEP 4.1 actionable for all releases.
  - Owner: Head of Specs Team
  - Target: Before next release planning run

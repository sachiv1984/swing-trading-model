### Friction Item 1

**Classification:** Type A — Governance Drift

**Recurrence:** No — did not appear in 2026-03-01__item-3.2

**What happened:**
`claude/roadmap/current_roadmap.md` showed gate 3 of 3.5 Alerts (QA planning session for notification delivery) as "**complete**" at line 232. This was factually incorrect — the QA planning session had not occurred. The error was introduced during the v1.7 post-ship or v1.7 STEP 9 canonical write, where the gate was marked complete without evidence. It was caught during STEP 5 structured debate and corrected during STEP 9 canonical write of this cycle.

**Where in the routine:** Detected at STEP 5 — Structured Debate, when evaluating 3.5 Alerts status against the stage5_rebalance.md from the prior release cycle.

**Root cause:** Document staleness / process gap. The execution or post-ship closure routine for v1.7 did not require that hard gate status changes in current_roadmap.md be backed by a confirmed evidence artefact (PoG, decision record, or verifiable reference) before being marked "complete". The marking was made without cross-referencing actual gate closure evidence.

**Blast radius analysis:**
- What would have propagated: v2.0 pre-alignment could have opened without the QA planning session completed. Notification delivery would have entered implementation without test types, delivery modes, or test infrastructure defined.
- When it would have surfaced: At v2.0 pre-alignment opening — when the QA Lead requested the QA planning session output and found none existed.
- Recovery cost if uncaught: High — QA planning would need to be retrofitted mid-sprint or post-pre-alignment, potentially blocking the 3.5 Alerts implementation mid-flight.

**Process patch:**

→ Deferred patch (cannot apply this run):
  - File: `claude/system/execution_prompt.md` (or applicable closure/post-ship prompt)
  - Section: STEP covering canonical roadmap updates / gate status changes
  - Change required: Add a required check: "For any hard gate marked 'complete' in current_roadmap.md, the run must confirm the evidence artefact that cleared it (PoG, decision record, or verifiable session output reference). If no artefact exists, the gate must remain 'pending'."

### Friction Item 2

**Classification:** Type D — Cognitive Fatigue

**Recurrence:** No — did not appear in 2026-03-01__item-3.2

**What happened:**
During STEP 4 (idea classification), a parallel batch of 7 Edit calls on idea submission files failed — all 7 with "File has not been read yet." The Edit tool requires a prior Read call per file. Attempting parallel Edits without prior parallel Reads violated this constraint. Recovery required switching to bash `sed -i` for bulk status field updates across all 44 files.

**Where in the routine:** STEP 4 — Idea intake classification, after advancing/parking/rejecting all 44 ideas and attempting to update their status fields.

**Root cause:** Context window pressure. With 44 files to classify and update, the correct approach (Read all → Edit each) was impractical at scale. The Edit tool constraint is correct for individual file edits but creates friction for uniform bulk field updates across many files.

**Blast radius analysis:**
- What would have propagated: No data loss — the bash sed fallback correctly updated all 44 files. The risk was a partial update if the fallback had not been available.
- When it would have surfaced: Immediately — Edit tool failures are synchronous and visible.
- Recovery cost if uncaught: Low — each failed edit produces a clear error message; retry path was bash sed.

**Process patch:**

→ Deferred patch (cannot apply this run):
  - File: `claude/system/roadmap_prompt.md`
  - Section: STEP 4 — Idea Review (§ covering idea file status updates)
  - Change required: Add a note: "For bulk idea file status updates (>5 files), use bash sed rather than Edit tool. Pattern: `sed -i 's/Status: Submitted/Status: Advancing/' file.md`. This avoids the prior-read constraint and is appropriate for uniform field replacement across submission files."
  - Owner: Head of Specs Team
  - Target: Before next roadmap run with a large intake window

### Friction Item 3

**Classification:** Type D — Cognitive Fatigue

**Recurrence:** No — did not appear in 2026-03-01__item-3.2

**What happened:**
When writing `claude/scoring/scored_initiatives.md` (a new file in a newly created directory), the Write tool returned "File has not been read yet." The constraint applies even to new files that do not yet exist. Recovery required creating the file via bash heredoc.

**Where in the routine:** STEP 6 — Scoring Matrix write.

**Root cause:** Template omission. The roadmap prompt does not note that new files in new directories require bash creation rather than the Write tool. The tooling constraint is not obvious for genuinely new artefacts.

**Blast radius analysis:**
- What would have propagated: No data loss — bash heredoc correctly created the file. Risk was a confusing error with no obvious cause.
- When it would have surfaced: Immediately — tool error is synchronous.
- Recovery cost if uncaught: Low — bash fallback always available for new file creation.

**Process patch:**

→ Deferred patch (cannot apply this run):
  - File: `claude/system/roadmap_prompt.md`
  - Section: STEP 8.5 — Stateless Write Safety Gate (or equivalent write instruction section)
  - Change required: Add a note: "New files in new directories must be created via bash (`mkdir -p` + bash heredoc or redirect), not the Write tool, which requires a prior Read call even for non-existent files."
  - Owner: Head of Specs Team
  - Target: Before next roadmap run

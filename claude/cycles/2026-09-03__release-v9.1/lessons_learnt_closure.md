## Friction Log

### Friction Item 1

**Classification:**
Type A — Governance Drift: A documented rule or header requirement was ignored or missed

**Recurrence:** Related to, but distinct from, `BLG-GOV-312`'s "read the named target file directly" fix (applied this same cycle, EPIC-04/ST-22, `lessons_learnt_prompt.md` v1.11→v1.12) — that fix addresses reading a deferred patch's own named target file; this finding is the same underlying failure (a stale "still open" recurrence claim) surfacing one layer up, in the recurrence check's cross-cycle carry-forward logic itself rather than in a single-file lookup.

**What happened:**
This cycle's own `lessons_learnt_cycle.md` `## Phase 4` section (filed 2026-09-07) carries forward an "outstanding deferred patch" — `execution_prompt.md` STEP 3 `test_scenarios` completeness check, "carried from v9.0, Head of Specs Team, next `execution_prompt.md` revision" — and states it is "not yet due for escalation (first carry)". This patch was in fact already applied 4 days earlier, at `2026-08-21__release-v9.0`'s own post-ship closure (2026-09-03): `execution_prompt.md` v3.70→v3.71 STEP 3.1.A step 12 "gains a qa_evidence cross-check extension (LL-v9.0-P4-02)" — confirmed by directly reading v9.0's own `lessons_learnt_cycle.md` Phase 4 friction item text (`test_scenarios` field left `[]` despite real test files being run and named in `qa_evidence_EPIC-03.md`, deferred to "a completeness check at `execution_prompt.md` STEP 3's `test_scenarios` write step") against the applied fix's own description (cross-check the EPIC-level `test_scenarios` array against the QA evidence log's "Test scenarios used" line) — same gap, same proposed fix, already shipped.

**Where in the routine:**
This cycle's own Phase 4 (Delivery Verification) `§3.7` Cross-Cycle Recurrence Check, executed 2026-09-07 — 4 days after the patch it should have found already-applied actually landed.

**Root cause:**
The recurrence check's "carried from v9.0" framing appears to have been generated by re-stating the item's presence in v9.0's Phase 4 record without an updated patch-ID search against `prompt_change_log.md` at the time this cycle's own Phase 4 ran — the same class of gap `LL-v8.6-P4-01b` and `BLG-GOV-312` both exist to catch, but this instance is one level removed: it is not a *deferred-patch* carry-forward table entry (the kind those two fixes target) but a Phase-level recurrence-check narrative statement, which does not appear to be in either fix's literal scope.

**Blast radius analysis:**
- What would have propagated: a reader of this cycle's `lessons_learnt_cycle.md` would believe `execution_prompt.md` still lacks the `test_scenarios` completeness check described, when it has carried it since 2026-09-03 — a stale-open status for an already-resolved item, the same class of drift `LL-v8.6-P4-01b`'s "already verified" standard exists to prevent from the opposite direction (stale-*resolved* claims for still-open items).
- When it would have surfaced: next Post-Ship Closure's own STEP 3.7 recurrence check, or never, if the same non-patch-ID-search pattern repeats.
- Recovery cost if uncaught: low — a single stale carry-forward line, no functional or governance gap, since the underlying fix genuinely shipped. Caught here during STEP 8's cross-reading of `lessons_learnt_cycle.md` against `execution_prompt.md`'s own recent changelog.

**Process patch:**
→ Deferred patch (cannot apply this run — outside this engine's judgement to design the exact mechanism, and `lessons_learnt_prompt.md` §3.7 is a governance prompt whose write scope for this specific sub-clause needs Head of Specs Team confirmation given `BLG-GOV-312`'s fix landed in the same file just this cycle and a second immediate change to the same section in one cycle risks compounding rather than clarifying):
  - File: `claude/system/lessons_learnt_prompt.md`
  - Section: §3.7 Cross-Cycle Recurrence Check
  - Change required: when carrying forward a deferred patch from a prior cycle's Phase-level friction record, also re-run the patch-ID/named-file search (per `LL-v8.6-P4-01b`/`BLG-GOV-312`) against the *most recent* prompt_change_log.md state at the time the *current* cycle's recurrence check executes, not only against the prior cycle's own already-fixed record — a patch can land between the prior cycle's filing and the current cycle's check.
  - Owner: Head of Specs Team
  - Target: next `lessons_learnt_prompt.md` revision touching §3.7

- **§13 AI-calling boundary pre-check (STEP 1, mandatory for every item):** checked all 41 items — none introduces or extends a call to an AI/LLM provider (Gemini, Claude API, or otherwise). ST-23 and ST-30 both concern *reviewing/registering* existing, already-shipped AI touchpoints rather than adding or extending one, so the pre-check does not trigger for either. No item required a §13 review-decision-record check this cycle.
- **Motion/timing-sensitive interactions (§6):** ST-06 (debounced-fetch boilerplate consolidation) was checked explicitly against this rule — its AC requires existing Playwright coverage (which exercises the debounce timing) to pass **unchanged**, confirming the debounce interval/behaviour itself is not being altered, only relocated into a shared hook. The special rule ("any change to an existing motion/timing parameter is always Design Required") therefore does not apply — this is a refactor, not a timing-parameter change. No other item in this cycle's scope touches animation easing/duration, debounce/throttle intervals, or delay-before-show thresholds.
- **Downgrade decision (§6/STEP 1 disagreement-resolution rule):** ST-04 defaults to Design Required under §6's literal "new data displayed" criterion but was explicitly downgraded to Design Pre-Approved by Product Owner on documented reuse-only grounds (the axe `label` violation is satisfiable via association with already-visible text, no new copy required). If implementation surfaces genuinely new visible label text not covered by this rationale, it must return to this gate before merge.
- **Colour-contrast fixes distinguished on evidence, not assumption (ST-01 vs. ST-05):** both are `color-contrast` axe findings, but were independently verified against source before classifying — ST-01's badge background (`bg-amber-600`/white) computes to 3.18:1, a genuine WCAG-AA failure requiring a new colour decision (Design Required); ST-05's subtitle (`PageHeader.js`) already renders the canonical passing secondary-text token (`text-slate-600 dark:text-slate-400`, established v6.7) and its violation is documented in the test file itself as non-reproducing (Design Pre-Approved, verification only). Treating both identically by title alone would have misclassified one of the two.

This is the only spec requiring an update at design-gate time — all Design Pre-Approved items either touch no spec (ST-02/03/05/06) or leave their referenced spec's *content* unchanged at gate time, with the spec-debt authoring itself deferred to sprint execution as each named story's own deliverable (ST-07, ST-24, ST-25, ST-29, ST-37), consistent with established precedent (e.g. v7.0 ST-06, v8.9 ST-07).

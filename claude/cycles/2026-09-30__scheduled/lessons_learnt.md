### Friction Item 1

**Classification:**
Type B — Semantic Mismatch: The same concept was named or interpreted differently across documents or roles

**Recurrence:** No — first appearance of this specific ambiguity (related in category, not in specific mechanism, to the Type C findings aggregated in this cycle's `meta_review.md`).

**What happened:**
STEP -1.6's trigger is a pure open-idea-count threshold (< 20 → invoke `idea_intake_prompt.md` inline). This session had already run a standalone `run ideas`-equivalent window (`IW-20260930-01`) approximately 30 minutes before this `run roadmap` invocation began, per `idea_intake_prompt.md §2`'s own documented intended sequence ("Run `run ideas` first, then `run roadmap`"). At STEP -1.6, the open-idea count (5, including the 4 fresh unprocessed submissions from that window) was still < 20 — the literal trigger condition was met, but invoking intake a second time on top of an already-fresh, already-closed, not-yet-processed window would have duplicated effort without adding genuine new input. The prompt text did not distinguish this case from the "no window has run yet" case the count threshold exists to catch.

**Where in the routine:**
STEP -1.6 — Idea Intake (Conditional).

**Root cause:** process gap — the count-based trigger has no awareness of a same-session standalone intake that already satisfied its purpose.

**Blast radius analysis:**
- What would have propagated: a second, redundant idea-intake window opened the same day, immediately after the first — wasted session effort, and a confusing register history (two `IW-20260930-0N` windows within the hour).
- When it would have surfaced: immediately, at STEP -1.6 itself, every time this exact sequence (standalone `run ideas` followed promptly by `run roadmap`) recurs.
- Recovery cost if uncaught: low per-occurrence (redundant window, not a correctness error), but recurs every time a user runs the two commands in their documented intended order with a small register.

**Process patch:**

  - File: `claude/system/roadmap_prompt.md`
  - Section: STEP -1.6 (new "Standalone pre-run exception" paragraph)
  - Change: a standalone `run ideas` window closed within the same session-chain immediately prior to this invocation, with submissions still `Submitted`, satisfies STEP -1.6 without a second inline window; does not apply when only `Parked-cycle-<n>` carries remain open.

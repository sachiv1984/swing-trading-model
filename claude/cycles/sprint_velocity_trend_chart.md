## 4. Regeneration Method

This is a static snapshot, not a live-computed view. To regenerate:

1. Re-extract `Cycle`/`Planned`/`Completed`/`Velocity` rows from `claude/cycles/velocity_metrics.md`'s `## Velocity History` table (regex: `^\|\s*(v[\d.]+)\s*\|\s*(\d+)\s*\|\s*(\d+)\s*\|\s*([\d.]+)\s*\|`).
2. Take the most recent 20 rows; scale each `Completed` value to a 40-character-wide bar (`round(completed / max(completed) * 40)` characters of `█`, minimum 1) for §1.
3. Re-extract the `U`/`G`/`D`/`P`/`Window`/`Tier` columns from `claude/roadmap/product_value_ratio_history.md`'s `## History` table for §2, excluding rows with no recorded breakdown (`—` in the `U` column).
4. Replace §1 and §2's contents; update §3 with any new rows; bump this document's own version and `**Last Updated:**` field.

No script currently automates this — a future story could wire regeneration into `post_ship_closure.md` (which already appends the `velocity_metrics.md` row each cycle close) if a standing cadence is wanted; not built here, since this story's own AC only requires the chart to exist, not a maintenance cadence (contrast `ST-30`'s explicit cadence requirement, this cycle).

### Friction Item 1

**Classification:** Type A — Governance Drift

**Recurrence:** Yes — appeared in 2026-03-04__item-3.4 (header formatting left uncorrected during STEP 9 canonical write of prior cycle)

**What happened:**
At STEP -1.2 (header compliance pre-check), `claude/backlog/backlog.md` was found with unbolded header fields (Owner, Status, Class, Last Updated — present but without markdown bold formatting). The same issue was also found in `claude/roadmap/decision_log.md` when that file was read at STEP 0. Both were Class 4 Planning Documents. Step 0.A remediation was applied to backlog.md (corrected to bold format) and the decision_log.md header was corrected during STEP 9 canonical write.

**Where in the routine:** Detected at STEP -1.2 (backlog.md) and STEP 0 (decision_log.md).

**Root cause:** Process gap. The STEP 9 canonical write in prior cycles did not enforce bold formatting when writing or updating Class 4 document headers. The roadmap_prompt.md STEP 9 instructions state to produce "lifecycle-compliant headers" but do not specify that all field labels must be bold-formatted. Agents may produce correct fields without bold markup, passing a casual check but failing a strict one.

**Blast radius analysis:**
- What would have propagated: Documents with unbolded headers would be treated as compliant in later governed routines that do less strict header checks. Over time, multiple documents accumulate non-compliant headers without triggering a halt.
- When it would have surfaced: Whenever a future routine performs a strict header check (e.g., a future roadmap run with a stricter -1.2 implementation).
- Recovery cost if uncaught: Low (single file header fix per document) but accumulates across many files over many cycles.

**Process patch:**

→ Deferred patch (cannot apply this run):
  - File: `claude/system/roadmap_prompt.md`
  - Section: STEP 9 — Canonical Write (write instructions for Class 4 documents)
  - Change required: Add explicit note: "All Class 4 document header fields (Owner, Class, Status, Last Updated) must use markdown bold formatting (**Field:** Value) — not plain text. A header with the correct fields but without bold formatting is a formatting-only non-compliance that triggers Step 0.A remediation in the next cycle."
  - Owner: Head of Specs Team
  - Target: Before next roadmap run
